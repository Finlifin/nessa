# 包源码加载实施记录

完整目标仍是 Nessa 设计实现与 delimiter 多栈 ABI。本阶段补齐包编译需要的
文件系统输入生产者；不代表包编译、跨包依赖、CLI 或 NSBC 库链接完成。

## 已实现行为

`pkg_manager` 的模块发现现在返回 `Result`，按包类型选择根入口，保留嵌套
`main.ns` / `lib.ns`，使用语言词法器验证完整模块名。同级排序稳定，文件与
目录同名、缺入口、非普通入口、I/O 错误、无效 UTF-8 和祖先链接循环显式报错。
目录别名保留逻辑路径，同级别名分别加载；不把物理路径加入包身份。

源码加载返回拥有文本的 `PackageSources`，保留完整 manifest 元数据和原始文本。
manifest、单文件、源码合计、目录条目、模块数与深度都有边界；恰好达到限制
允许，超限拒绝，不截断文本。打开文件前检查其类型，避免静态 FIFO manifest
阻塞；打开后再次检查实际文件类型。并发外部替换文件不提供原子快照保证。

生产者与测试作者使用不同副本。根代理负责生产实现与唯一合并；独立测试先按
冻结 API 编写，再读取封存生产文件执行。冻结标准与运行记录分别保存在
`/tmp/nessa-package-source-contract.md` 和 `/tmp/nessa-package-source-graph.json`。
