# 受检 AST 源码单元合并

`Ast::validate_storage` 检查空节点哨兵、根索引、四个固定子索引、所有多子节点范围、
保留的子节点槽位及环。验证采用显式栈，允许共享子树、未被根引用的节点和 null
占位；深层 AST 不依赖原生调用栈递归。这里检查存储结构，不代替语言语义检查。

`try_append_ast` 与 `try_append_asts_with_limits` 在修改逻辑内容前验证全部输入。
容量统计包含哨兵和所有保留槽位，恰好达到限制允许；超限、非法索引或环返回
`AstAssemblyError`。容量预检先于环验证的临时分配。需要的节点、子节点、原始
范围、来源记录和返回根索引存储预先保留；失败时目标的节点、根、原始文本和
子节点内容不变，分配容量可能增长。批量合并只验证目标一次、每个来源一次，
避免逐文件重新扫描不断增长的目标；重定位保留 null、Span 和原始文本归属。

std 加载器已通过 driver 的受检适配器合并源码单元，九个模块正文一次批量
追加，保持声明顺序和可信节点边界。合并错误发出普通编译诊断并返回错误。
原来的可信 `append_ast` 接口仍保持其已有契约；包文件消费者应使用受检路径。
