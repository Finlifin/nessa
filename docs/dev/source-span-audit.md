# 源码位置与原始文本

lexer 和 parser 读取原始 UTF-8 文本。`rustc_span::SourceMap` 会移除开头的 BOM，并把 CRLF 转成 LF；原始字节位置不能直接用于 SourceMap 的诊断和 snippet。

`source_span` 负责检查并转换两套坐标，仅依赖 `rustc_span`。parser 在完成解析时统一转换节点和解析错误的位置；lexer 在发出诊断时转换错误的位置。解析后的语义诊断和两个渲染器使用已经转换的位置，不再次转换。注册文件的原始文本不匹配、范围越界、字符边界错误或位置溢出会明确拒绝输入。

AST 保留原始源码和每个节点的原始范围。追加另一个文件的 AST 时，同时移动该文件的文本和范围归属；调试输出不会用主文件的文本解释追加文件的位置。源文件缺失时不制造原始文本。坐标元数据采用 `Arc`，不改变 AST 的 `Send` 性质；临时映射器共享 SourceFile 已有的文本，不在 AST 中保存 `Rc`。

BOM 仍是现有语言规则下的词法错误。移除的 BOM 映射为所属文件开头的零宽范围，附带文件归属，和没有来源的 `DUMMY_SP` 分开。两个诊断渲染器验证文件归属、范围和字符边界；没有可显示的同文件标签时，为主范围创建精确位置标签，使文件和行列仍然显示，不扩大错误范围。

本次不预处理 lexer 输入，不改变字符串、宏的原始字节，也不改变 TypeId 编码或 NSBC 格式。普通字符串内的实际 LF/CRLF 仍被拒绝；测试用合法的单独 CR 字符和外围 CRLF 检查字符串文本，用宏原始内容检查跨行字节。
