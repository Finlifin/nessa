# 跨包源码编译实施记录

本阶段把调用者持有的多个 `PackageSources` 接入同一编译管线。完整项目目标
仍在进行；依赖下载、目录映射、CLI 自动获取依赖及外部归档链接尚未实现。

`Driver::compile_package_sources_with_dependencies(root, catalog)` 注册完整清单，
沿现有解析器选择全图一致的确切版本；只解析选中且可达的源码树。旧单包入口
使用空 catalog。诊断路径不被重新打开，根与依赖共享解析、解析后的类型检查、
NIR、codegen 和 NSBC 后端。只有根 exe 的零参数 main 被调用。

同一完整包名和版本的重复清单必须一致；源码的模块路径与原始内容也必须
一致，物理路径与目录表顺序不参与比较。未选中的版本不解析。选中的全图
合计最多 65536 个源码模块、64 MiB 原始源码，并保留单文件 16 MiB、单包
层级等既有检查；异常返回普通诊断和空编译结果。真实系统 OOM 未强制注入。

依赖包通过不进入父词法绑定的合成模块容器装配。`use` 先查当前包内部的
词法名称，再按当前包清单的直接依赖查短名；传递依赖不自动可见。
普通表达式使用依赖前需显式 `use dep` 或导入其成员。同名本地模块遮蔽依赖；
不可见本地名称仍报错，不退回依赖。多个直接依赖短名相同且被选中时明确
报歧义。`@` 从当前包根解析；外部包的父路径不能越过自己的根。

每个源码包有独立弱 std prelude，消费者的同名声明不会覆盖它；std 源码仍
是唯一由这条入口赋予 builtin 权限的来源。合成容器的身份使用内部不可词法
声明的 `<package-root>` 路径段；子声明去掉容器路径，保留原包源码路径。
这避免与同名真实模块碰撞，保持独立编译、不同消费者及导入别名之间的完整
128 位 TypeID 一致。既有 std 路径与 TypeID 不变。

成功导入保留所选命名空间的符号事实，让选择性嵌套导入也加载实际依赖包根
的初始化钩子。未使用的清单边不触发初始化；共享菱形依赖只初始化一次。
归档保留包类型身份、全局存储、函数和启动入口，执行不再依赖源码树。

独立隔离测试覆盖三包版本选择、重复与图错误、全图容量、可见性与重导出、
直接依赖限制、歧义与遮蔽、包根及前向类型别名隔离、菱形初始化、独立
prelude 和权限拒绝、完整类型身份及归档往返。根另外补了同名模块容器回归
和选择性嵌套导入加载根钩子的对照。首轮确实发现模块符号重复创建；失败
日志保留，修复复用预声明符号。后续同名容器碰撞也有先失败后修复的记录。

验收以本次实际命令与独立评分工件为准；测试通过本身不代表完整项目完成。

独立验收在全仓 1845/0/1 和严格质量检查通过后，额外复现了消费者局部扩展
泄漏，以及包装使原本合法的 256 段类型路径越界。首个图达到修复预算后保留
未通过结果；窄续修图沿用全部原验收条件。已分别检查源码关联成员选择、
持久化方法/trait/dispatch 的包边界，并让合成容器不占原始路径预算。独立
失败案例纳入永久回归；元数据测试还检查快照恢复后的权限。最终复验仍待
实际工件确认。跨包 trait 的默认成员仍按包可见性处理；显式公开 trait 成员
语法尚待完整项目后续实现，不通过修改默认可见性绕过它。
