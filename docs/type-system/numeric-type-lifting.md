# 数值类型提升 (Numeric Type Lifting)

nessa 采用类似 Julia 的数值类型提升规则，但在编译期静态编码，而非运行时动态分派。

## 基本规则

当两个不同数值类型参与运算时，编译器根据提升规则自动将较窄的类型提升为较宽的类型：

```nessa
let a: i32 = 10
let b: f64 = 3.14
let c = a + b          -- a 被提升为 f64，c: f64
```

## 提升层级

整数提升遵循宽度和符号性规则：

```
u8 -> u16 -> u32 -> u64 -> u128
i8 -> i16 -> i32 -> i64 -> i128
u{N} -> i{N*2}  (无符号可提升为双倍宽度的有符号)
整数 -> f32 -> f64
```

## 静态编码

与 Julia 的运行时提升不同，nessa 的提升规则完全在编译期解析：

- 编译器在类型检查阶段确定提升路径
- 生成的代码中包含明确的类型转换指令
- 不存在运行时的类型判断开销

```nessa
-- 编译器将此展开为：
-- let c = (a.as(f64)) + b
let a: i32 = 10
let b: f64 = 3.14
let c = a + b
```

## 无隐式窄化

提升只发生在安全的方向（窄 → 宽）。反方向的窄化转换必须显式进行：

```nessa
let x: f64 = 3.14
-- let y: i32 = x        -- 编译错误：不允许隐式窄化
let y: i32 = x.as(i32)   -- 显式转换
```
