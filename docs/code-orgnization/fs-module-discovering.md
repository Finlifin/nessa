# 文件系统模块发现 (Filesystem Module Discovering)

nessa 采用类似 Rust 的文件系统模块映射方式，源码文件和目录结构直接决定模块树的形状。

## 入口文件

每个包有一个根入口文件，取决于包的类型：

| 包类型 | 入口文件 |
|--------|----------|
| 可执行程序 (`exe`) | `src/main.ns` |
| 库 (`lib`) | `src/lib.ns` |
| 临时包 (`tmp`) | `src/lib.ns` |

入口文件定义了包的根模块，所有其他模块都是根模块的子模块。

## 模块映射规则

从入口文件所在目录开始，递归地：

- 每个 `.ns` 源码文件被视为一个子模块，模块名为文件名（去掉 `.ns` 后缀）
- 每个子目录被视为一个子模块，模块名为目录名，其入口文件为目录内的 `mod.ns`

只排除当前目录的入口：根目录排除所选包入口，子目录排除自己的 `mod.ns`。
例如库根目录的 `main.ns`、子目录里的 `main.ns` 和 `lib.ns` 都是普通子模块。
同级模块按名称排序；同名文件和目录（例如 `net.ns` 与 `net/mod.ns`）构成冲突，
必须报错，不能由目录枚举顺序决定采用哪个。

目录符号链接按逻辑模块路径遍历。规范化目标若指向当前遍历链的祖先，报告循环；
不同同级别名指向同一目录时仍是不同逻辑模块。诊断保留别名路径。
缺失入口、非普通文件入口、无效名称和 I/O 错误必须返回错误，不能返回部分模块树。

## 示例

假设有如下文件结构：

```
my_package/
├── package.toml
└── src/
    ├── main.ns            -- 根模块（包入口）
    ├── utils.ns           -- 模块 utils
    ├── net/
    │   ├── mod.ns         -- 模块 net
    │   ├── http.ns        -- 模块 net.http
    │   └── tcp.ns         -- 模块 net.tcp
    └── db/
        ├── mod.ns         -- 模块 db
        └── driver/
            ├── mod.ns     -- 模块 db.driver
            └── postgres.ns -- 模块 db.driver.postgres
```

对应的模块树为：

```
root (main.ns)
├── utils
├── net
│   ├── http
│   └── tcp
└── db
    └── driver
        └── postgres
```

## 命名约束

模块名遵循蛇形命名法（`snake_case`），因为模块名直接来源于文件名和目录名，所以文件和目录也应使用蛇形命名。

蛇形命名是风格约定。加载器用语言词法器检查完整标识符，允许 Unicode 标识符，
拒绝关键字、包含空白或运算符的名字以及非 UTF-8 模块名。

## 源码加载边界

`pkg_manager::load_package_sources` 读取完整 manifest 和模块文本，返回拥有数据的
`PackageSources`，保留 manifest 元数据、逻辑模块路径和物理诊断路径；不编译源码。
包根目录规范化用于诊断，不参与包身份计算。文本不进行裁剪、换行替换或有损解码。

默认限制：模块深度 256、模块总数 65536（含根模块）、目录条目总数 262144，
manifest 1 MiB、单个源码文件 16 MiB、源码合计 64 MiB。忽略的普通文件也计入目录条目，
每个逻辑别名的文本分别计入源码合计。可通过 `SourceLoadLimits` 调整，所有限制必须
为正数，深度不得超过 256；恰好达到限制允许，超限或无效 UTF-8 返回错误。

该加载接口只提供文件输入。`driver::Driver::compile_package` 将这些文件分别解析，
通过受检 AST 合并生成模块树，再使用单文件编译共用的名称解析、NIR 和代码生成管线。
`compile_package_sources` 接受拥有文本的 `PackageSources`，不重新读取其中的物理路径；
调用者构造的树同样检查默认深度、模块数、单文件及总源码字节限制。

CLI 的 `run`、`check`、`build` 接受包目录。`build` 输出目录内的 `package.nsbc`，
`--emit-ast-dump` 输出 `package.lisp`；单文件输入仍输出同名扩展名文件。源码错误
保留各文件的物理路径和准确位置，诊断输出到 stderr。NSBC 归档可在删除源码后运行。

依赖源码选择、跨包名称解析和外部库归档链接仍需继续实现；已声明但不能解析的依赖
返回错误，不会被默默省略。目录编译不等于完整包管理。

## 与内联模块的关系

除了文件系统映射，nessa 也支持在源码中直接定义内联模块：

```nessa
mod inline_module {
    fn helper() -> i32 = 42
}
```

内联模块和文件系统模块在语义上完全等价，都是关联作用域的实例。文件系统映射只是一种便捷的隐式声明方式。

同名空模块声明（`mod utils` 或 `mod utils {}`）连接文件系统模块，保留原有
`pub`/`private` 修饰及其作用域规则。带内联正文的同名模块、其它同名绑定和重复
声明均报告冲突。隐式生成的模块采用普通包内可见性，用户模块不获得 std 的可信权限。
